01 / Overview

What was the problem?

The initial brief focused on color, corners and spacing. Underneath, recurring visual and interaction patterns had drifted apart.

  • Typography without one consistent scale
  • Different color and styling decisions
  • No shared component baseline
  • Interaction patterns that varied by page

03 / Design in practice

Clear status. Explicit actions.

Data Import shows the principle in practice: make the current state clear, and give the next action an explicit place.

Let status explain the present. Let actions show the next step.

In Data Import, the status cell had doubled as an entry point. We separated those responsibilities: status describes the file, while a dedicated Action column exposes Review Data and other next steps. Combining report name and date into one file-oriented cell made room for the action column.

More design examples · navigation, templates and Review Data

Keep important destinations from disappearing.

The old fixed-width navigation placed account switching beside the logo. As available modules changed between accounts, destinations could move into the overflow menu. The redesign moved switching to the profile area and regrouped destinations by intent, including moving Assumptions under Planning.

Vertical navigation offered additional capacity as an optional setting. Experienced advisors could keep the horizontal arrangement they already knew.

Navigation redesignRegrouped · Responsive · Horizontal or vertical

Keep templates visible while editing.

Templates previously lived behind a dropdown. A list-and-editor layout keeps available templates in view, adds a visible New Template entry and supports reordering through drag handles. Switching a template no longer requires returning to a hidden list.

Make read-only information look read-only.

The old Review Data drawer made non-editable fields resemble disabled dropdowns. The revised treatment presents them as read-only information, avoiding the suggestion that a control might become available.

Separate selection from navigation.

Checkbox text had also acted as a link, creating ambiguity about whether a click would select an item or navigate. The redesign gives selection and linking independent targets.

A six-participant internal pilot surfaced how existing habits shaped Activity entry-point discovery. We adopted the team’s recommended toolbar approach. Feedback was collected for later prioritization with product; it did not trigger another redesign round before launch.

Read the testing evidence · two prototypes, observations and follow-up
Participants

Six internal colleagues familiar with RightCapital, including customer-facing support, training and sales perspectives.

Method

Moderated one-to-one sessions, think-aloud tasks and two clickable prototypes, followed by a Household-page walkthrough.

Task

Find the task associated with the first activity and open its details. Several sessions also asked participants to review or edit it.

Two entry points. The same task.

The pilot examined how people distinguish opening details from other activity actions. Option A exposed a separate icon toolbar on hover; Option B placed direct links inside the activity text.

A separate action toolbar

Option B · Alternative explored

What the sessions revealed

01 / Learned behavior

Existing habits shaped the search.

One participant explained that the three-dot menu meant editing because that was how the existing product worked. Another first tried the entire activity row, then followed the visual change on hover. A familiar action area helped some participants orient themselves.

02 / Discoverability

A direct link still has to look actionable.

Some participants did not initially notice the underlined task text. One recognized the entry point after seeing the underline and preferred the direct route; another suggested a distinct link color before hover. Preferences differed, revealing a tradeoff between a direct path and a familiar entry point.

03 / Icon meaning

Finding a button did not guarantee understanding it.

A participant paused over the details icon to check its meaning and suggested clearer labeling or a more familiar symbol. The toolbar also needed to communicate what each action would do.

Design decision

We adopted Option A, the design team’s recommended direction.

The sessions provided qualitative evidence about familiar action patterns, overlooked links and unclear icons. They also identified discoverability concerns for follow-up within the chosen direction. Adoption was a team decision; these sessions do not establish a quantitative winner.

A second lens: the Household experience

Participants also explored the implemented Household test page. Feedback described clearer invitation inputs, access states and navigation while retaining familiar functionality. The review surfaced concrete issues: truncated status labels on smaller screens, small supporting text, faint controls and additional scrolling. These findings identified concrete issues to track through review.

Collect feedback now. Prioritize changes for the next release.

This pilot primarily gathered feedback. With a fixed delivery timeline, we did not run a follow-up redesign round before launch. Suggestions would be discussed with product and prioritized for a later version.

Discoverability / proposed follow-up

Explain icons and reveal truncated text.

The proposed response was to add hover tooltips: explain an icon’s action and reveal the full label when text is truncated. These were follow-up solutions, rather than changes validated in a second test round.

Typography / retained decision

Keep the agreed type scale.

We retained the existing font sizes, as agreed at the start of the redesign. Revisiting typography would have expanded the scope beyond the time and capacity available for this release.

Study scope and interpretation

This was an internal formative pilot, not a study with six external financial advisors. Familiarity with the existing product shaped expectations. Some tasks required moderator clarification, and one participant was distracted by a test-platform example task. The transcripts support qualitative findings, not comparable task times, first-click percentages, deletion-safety rates or post-launch impact.
